Prototype · runnable slice of the solution design

A disruption call, end to end, running on your laptop.

Caller text goes in through a Genesys simulator, the Zingly voice agent identifies the caller and answers through a real MCP server, and the MCP server protects a mocked airline reservation system that refuses anything above 5 requests per second. Every handover produces the Genesys screen-pop payload. No LLM and no API key: the agents run in the design's deterministic mode.

Quick start

IT architectReviewer

One script sets up Python, frees busy ports gracefully, and starts the four servers in dependency order.

cd prototype
./start_up.sh                                        # venv + install + start all four servers
.venv/bin/python scripts/run_flow.py --list          # the 14 demonstration flows
.venv/bin/python scripts/run_flow.py happy_rebooking --trace
.venv/bin/python -m genesys_sim --trace              # interactive call in the terminal
open http://127.0.0.1:8090                           # softphone + agent desktop in a browser
.venv/bin/python scripts/spike.py                    # load spike: unprotected vs protected
./start_up.sh stop

Also restart, status, test and logs <name>. If a port is taken, whatever listens on it gets SIGTERM, then SIGKILL after a grace period.

Architecture

IT architect

The voice agent reaches the airline only through the MCP server, where the policy engine and the saved copy protect the reservation system for every client.

Why here

Policy inside the MCP server

The voice agent, Codex and the MCP Inspector all pass the same guard, booking-scope check, lanes and saved copy. The voice agent holds no reservation code at all; an architecture test enforces it.

Identity

Signed, never a tool argument

Auth signs a short-lived identity token after verification. It travels in MCP _meta, so a model can neither see nor forge it, and booking tools act only on the booking named in it.

Honest seams

Text now, voice later

The Channel, IntentClassifier and DomainAgent interfaces are where LiveKit audio and LLM agents plug in. Nothing behind them changes.

Reservation protection

IT architectSecurity

Every reservation call passes identity, guard and scope checks, then degrades instead of failing when a lane is full. Writes are never served from the copy and never retried blindly.

6

Multi-tenancy

IT architect

One deployment, one config file: each process builds a runtime per tenant, and a call is matched to its tenant by the dialed number.

MCP server

IT architect

A real Model Context Protocol server on the official Python SDK: Streamable HTTP per tenant and stdio, so Codex or the MCP Inspector can use it directly.

ToolNeedsLaneNotes
get_flight_statusnothingP3Saved copy first, single-flight on a miss
get_alternativesnothingP2Fresh for 25 s, then one loader per route
lookup_caller_idnothingP1Masked summary only, never booking data
verify_bookingnothingP1Booking only on a match; throttled per booking, whoever asks
get_bookingVERIFIED token for that bookingP1Live first, saved copy as the "as of" fallback
rebookVERIFIED token for that bookingP0Idempotent; deferred when P0 is saturated; reconciled when a timed-out write cannot be read back
Connect Codex (stdio)
[mcp_servers.zingly_atlantica]
command = "/path/to/assignment_zingly/prototype/.venv/bin/python"
args = ["-m", "mcp_server", "--stdio", "--tenant", "atlantica"]
env = { "ZINGLY_TENANTS_CONFIG" = "/path/to/assignment_zingly/prototype/config/tenants.yml" }

Streamable HTTP endpoint: http://127.0.0.1:8100/atlantica/mcp. Full guide: MCP_SERVER.md.

Tests & production

IT architectSecurity

56 automated tests run with ./start_up.sh test; the module boundaries and contracts stay, the default implementations get swapped for production.

Before the first caller

Close the security gaps

  • Authentication on the gateway, MCP server and handover context
  • Remove the demo admin switches
  • Identity-token keys in KMS, short expiry
Swap the implementation

Same interfaces

  • Text channel → LiveKit participant
  • Templates → LLM agents via the AI gateway
  • In-memory state → Redis + a durable queue
  • Custom tracer → OpenTelemetry
Already in place

Behaviour to keep

  • 0 × 429 under the spike
  • Read-before-retry, idempotent reconciliation
  • Every failure ends in a person
